# Web 全局页面与资源管理

本说明对应跟进上游 `a189980f` 的未发布工作树。桌面、手机浏览器共用同一套受访问密钥保护的 Web API；文件路径和工具操作都属于运行 Rust 服务的主机。

## 导航与账号

侧栏先列 MCP、Skills、提示词和统一供应商，再列会话、用量和账号。展开侧栏覆盖页面左侧，不改变正文宽度；手机使用导航抽屉。所有供应商及账号引用的供应商名称按显示名 A–Z 排列，忽略大小写；添加供应商时的预设按登录、厂商、第三方、云、本地、插件分节，节内按显示名 A–Z。均不展示赞助、合作、星标或推广排名。故障转移执行队列保持原优先级。

账号中心按 Copilot、ChatGPT、xAI 分组，显示额度、默认账号、重新认证状态及供应商引用。删除账号前会列出受影响的供应商；删除不会自动替这些供应商选择其他账号。供应商表单只负责选择账号；账号选择处的「添加或管理账号」（Kimi Code、DeepSeek 账号预设为「管理账号」）在表单上方打开全屏授权中心并定位到对应分组，关掉后回到表单，草稿保留。Copilot Enterprise 域名登录仍不支持；禁用入口不会发起认证。各档额度默认写剩余，可在「设置 → 通用 → 外观 → 额度显示」改为已用，颜色仍按剩余算（不到 20% 标橙、用完标红）；余额、ChatGPT 订阅的 Codex Credits 和存下的重置次数始终写剩余，余额用完或欠费时照写金额并标红。

托管 ChatGPT 模型拉取使用指定账号或默认账号的有效凭据；切换账号后迟到结果不覆盖新账号列表。模型发现和生成请求共享客户端身份 `0.159.0`。原生 Codex 官方目录镜像仍使用服务主机检测到的实际 CLI 版本，两者独立。

## MCP 与 Skills

MCP/Skills 单项开关立即显示目标状态，写入失败回滚。列标题批量开关只影响搜索或筛选后可见的结果，成功条目可撤销；失败条目单独报告。MCP 页与 Skills 已安装一样是应用矩阵：页头放检查连通性、从应用导入、添加和「⋯」（重新同步到各应用、复制全部 JSON）；每行显示连通状态点、显示名与 ID、命令或地址摘要，单元格写入失败时格子标黄并在行内与页顶通知条提供重试（通知条的重试按应用重新同步，先写文件后入库的应用按每行想要的值逐格重写）；行尾「⋯」可测试连接、复制 JSON、打开文档、在全部应用启用 / 停用或删除，点击行打开编辑页。Oh My Pi 列的列头弹层说明它还会读取其他 Agent 的配置。窄屏下矩阵横向滚动。Skills 的「已安装」与「发现」在同一页用页签切换：已安装为应用矩阵，表头全选框只选当前筛选出的行，勾选后可批量启用、停用、更新或卸载；发现结果与已安装同为列表行，从发现跳回已安装时对应行会闪烁标出。发现列表按可视区域渲染。

“立即重新同步”（Skills 在页面「⋯」菜单的存储弹窗里）将已保存的启用配置重新投影到应用，报告每个应用及失败技能的原因。MCP 支持 Claude、Codex、Gemini、Grok Build、OpenCode、MiniMax Code；Hermes 的旧 Web MCP 写入仍未支持，不作为成功同步目标。Skills 同步支持上述应用及 Hermes，Desktop、OpenClaw、Pi 的原生目录不由此重新同步接管。

Skills 发现和更新检查同时返回成功条目与失败仓库；存在失败仓库时不能据此判断全部技能已经最新。skills.sh 的重试会重新请求；ZIP 安装跳过重名目录时显示原目录与已安装技能名称。

存储弹窗展示服务主机的实际目录；Skills 从页面「⋯」菜单打开，已安装行的「复制目录路径」复制的也是服务主机上的路径。`auto` 优先符号链接、失败后回退复制；`symlink` 强制符号链接；`copy` 强制复制。迁移主副本沿用存储设置中的确认流程。默认 Web 技能目录是 `~/.cc-switch-web/skills`，不会写入桌面版 `.cc-switch`。

## 提示词、记忆和用量

提示词可复制到其他应用，每个目标创建独立、未启用的新记录，不覆盖同名项。部分失败会保留错误与失败目标，再次复制只重试这些目标。Hermes 的 `SOUL.md` 是人设文件，应按内容选择是否复制。Pi 原生文件导入没有不可执行的撤销入口；删除仍沿用 Web 确认流程。

Hermes 记忆页切换两个文件时保留各自草稿，保存只针对当前文件。用量页显示服务进程最近一次后台或手动扫描的完成时间，每 30 秒刷新；进程尚未扫描时不显示。该时间表示扫描完成，不能代替同步结果中的错误明细。自动扫描模式下，服务端每 10 分钟兜底扫描一次会话日志；用量页打开且窗口可见时，按页面选择的间隔另行扫描。有新用量写入（代理记账、会话导入、归档、Codex 重建）时，服务端经 `GET /api/events` 推送事件，用量页随即重读统计（200 毫秒内的多次写入合并为一次）；没有新用量时不重读，只有「今天」这类随时间移动的范围每分钟重算一次。统计中的 Token 总数含缓存写入与命中，Codex、Gemini、Grok Build 的输入先扣除其中已含的缓存（每行记有输入 Token 语义：新写入的行按含缓存读写扣除，旧行按迁移前的口径保留）；每条请求记下写入时实际用于计价的模型（`pricing_model`），按请求模型计价或路由接管时它可能与模型不同：请求详情另列「计价模型」，模型统计与模型筛选优先按它，之后补上定价时也按它重算缺失的费用；按天汇总保留请求模型与计价模型两个维度；Claude Desktop 网关的用量并入 Claude Code 展示。金额换算只影响显示，库内费用一律为美元；只有选择自动获取汇率时，服务端才请求 open.er-api.com，失败时改用 floatrates.com。Web 模型测试会实际发起模型请求，因此保留模型、超时和重试设置。

用量页自上而下是页头（同步按钮显示最近同步时间，旁边齿轮打开「用量设置」抽屉）、范围栏（时间范围、按应用筛选、供应商 / 模型级联筛选）、概览（指标条加趋势图；时间范围选「全部」时换成热力图，可展开更早的每 53 周一段）和明细（请求日志、供应商、模型三个页签，页签上带条数）。应用筛选只列应用页设为显示的应用；供应商筛选与供应商统计按显示名 A–Z，不按请求数或金额排名。会话日志导入的用量显示为「应用 · 会话日志」。用量设置抽屉里有会话日志自动扫描与间隔（5 / 10 / 30 / 60 秒，关掉自动扫描后间隔隐藏）、「记录请求用量」的入口、Codex 用量重建、显示（币种与汇率、侧栏「今日」显示的项、请求日志的列、趋势图柱形或曲线面积）和定价入口。时间范围、页签、指标和每页条数记在浏览器本地；显示设置随 Web 设置保存。侧栏展开时「用量统计」后面显示今日数字，收起时放在悬停标题里。热力图的每一天可用键盘聚焦查看。

会话页的「搜索消息正文」默认关闭，从「⋯」菜单或搜索无结果时的按钮开启（设备级设置 `sessionContentSearchEnabled`）。开启后服务端在数据目录（默认 `~/.cc-switch-web/session-index.db`）建 SQLite FTS5 索引，只收用户与 Agent 的正文，不收思考、工具参数与输出和注入内容；索引只是缓存，不进主库、不参与备份与 WebDAV 同步，关闭时连同 `-wal` / `-shm` 一起删除。每次会话列表读取成功都在后台增量同步一次（文件按修改时间与大小、SQLite 来源按会话行的散列判断，没变的不重新解析），进度经事件推送 `session-index-status`。搜索结果只包含当前会话根目录内的来源，与读取会话内容用同一条路径校验。

## 新增或调整的 API

所有路径均沿用 Web 访问密钥保护，配置访问密钥时须发送 `Authorization: Bearer <key>`。

| 方法与路径 | 请求与结果 |
| --- | --- |
| `GET /api/auth/codex_oauth/models?accountId=...` | 可省略账号以使用默认账号；返回可选模型列表 |
| `POST /api/mcp/resync` | `{apps?: string[]}`；省略时同步受支持应用，去重目标并返回逐应用结果；不支持的目标返回 400 |
| `POST /api/skills/resync` | 返回逐应用结果及 `failedSkills`；不接管排除应用的原生目录 |
| `GET /api/skills/storage-paths` | 返回 `ccSwitch`、`unified` 两种存储位置的实际路径 |
| `GET /api/skills/discover` | 返回 `{skills, failures}`，失败包含仓库坐标与原因 |
| `GET /api/skills/updates` | 返回 `{updates, failures}`；前端旧数组 API 继续由兼容包装提供 |
| `POST /api/skills/install-archives` | 安装结果增加 `skipped` 诊断，已安装条目照常返回 |
| `GET /api/usage/session-sync` | 返回最近扫描完成的 Unix 毫秒时间或 `null`；既有 POST 仍触发手动同步 |
| `GET /api/usage/summary`、`/trends`、`/provider-stats`、`/model-stats` | 查询参数在 `startDate`、`endDate`、`appType` 外增加 `providerName`（展示名精确匹配，含会话占位名）与 `model`（有效计价模型精确匹配：计价模型优先，没有时用模型）；汇总增加 `realTotalTokens`、`cacheHitRate`，供应商统计增加 `appType` 与首字中位数，模型统计增加成功率、速度与首字中位数 |
| `GET /api/usage/summary-by-app` | 同上的时间与供应商、模型筛选，按应用返回 `{appType, summary}`，按真实 Token 降序 |
| `GET /api/usage/first-date` | 同上的应用、供应商、模型筛选，返回最早有用量的本地日期 `YYYY-MM-DD` 或 `null` |
| `GET /api/usage/exchange-rates` | 返回 `{rates, fetchedAt, source}`：1 美元折多少 CNY / EUR / JPY / TWD / TRY；两个源都失败时返回错误 |
| `POST /api/sessions/content-index/sync` | 在后台把正文索引同步到当前会话列表，立即返回 `{running, processed, total}`；已在同步时只排一次重跑；功能关闭时不碰磁盘 |
| `POST /api/sessions/content-search` | `{query, providerIds?, limit?}`；按会话聚合返回 `{hits, status}`，每个命中带最多 3 条摘录（`messageIndex`、`text`、UTF-16 高亮范围）与命中消息数；`limit` 最多 200 |
| `DELETE /api/sessions/content-index` | 删除正文索引文件，返回 `true` |

测试使用临时目录、内存数据库、本地 HTTP 夹具和浏览器全 API mock。真实账号登录、工具安装、跨平台编译、全量测试、发布构建和 Docker 验证不包含在本轮验收内。

## 服务端事件推送

浏览器与服务端之间有一条共享的事件长连接（`GET /api/events`，SSE），代替原先的定时轮询，事件名与上游桌面端一致。访问密钥照常经 `Authorization` 头校验，所以前端用 fetch 读流，而不是浏览器自带的 EventSource。第一个订阅者出现时建连，最后一个离开时断开；断线后按 1、2、4…最长 30 秒退避重连，重连上后整体重取一次数据（断线期间的事件已经漏了），服务端判定页面跟不上时同样发 `resync`。经反向代理部署时，响应带 `X-Accel-Buffering: no` 与 `Cache-Control: no-cache`，每 15 秒发一次保活注释，代理的读超时应长于 15 秒。

目前推送的事件：`usage-log-recorded`（新用量写入，用量页重读统计）、`provider-switched`（故障转移切到另一家、开启故障转移、应用项目后，供应商列表与模式视图刷新；模式视图因此不再每 3 秒轮询）、`profile-applied`（项目、MCP、Skills、代理状态与提示词面板刷新）、`universal-provider-synced`（统一供应商增删与同步）、`webdav-sync-status-updated`（WebDAV 自动同步结果，失败时提示）、`session-index-status`（会话正文索引进度，会话页边建边重查）。
